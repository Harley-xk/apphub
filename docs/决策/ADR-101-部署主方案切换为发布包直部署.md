# ADR-101：部署主方案切换为发布包直部署

- 状态：已接受
- 日期：2026-10-22
- 关联：[发布包打包与部署指南](../指南/发布包打包与部署指南.md)（主方案）；[Docker 打包与部署指南](../指南/Docker打包与部署指南.md)（备选）；[ADR-005](ADR-005-数据库迁移策略.md)（迁移随发布执行，两方案一致）

## 背景

本仓库此前以 Docker 单镜像（node + nginx 多阶段构建、compose 编排、云效主机部署）为唯一部署形态（upstream 同源工具链，2026-10-20 完成容器名 apphub 定名）。2026-10-22 upstream 交付发布包直部署工具链（tar.gz 发布包 + systemd + 全局 nginx 分流，docker 降为备选），经评审决定随同步切换本仓库部署主方案。

## 决策

1. **主方案切换为发布包直部署**：生产上线（appcenter.witice.top 单机）采用 tar.gz 发布包 + systemd（`apphub.service`）+ 全局 nginx 站点分流（`nginx-site.conf.example`）形态；发布经 `scripts/build-release.sh` 构建产物、云效流水线分发、服务器 `release.sh` 执行「解包 → 覆盖 → 迁移 → 重启 → 健康探测」。
2. **Docker 单镜像降为备选**：工具链（Dockerfile、compose、deploy.sh）完整保留，向容器平台演进或多机分发时启用；两方案共用同一份 `server.env`（仅注入方式不同）。
3. upstream 部署类 ADR-006/007/008 已随同步删除（部署方案细节收敛于两份平级部署手册）；本仓库主备选型结论由本 ADR 承载。

## 理由

1. **服务器组件最简**：目标服务器单机常驻，发布包方案只需 node 22 + systemd + 全局 nginx，不引入 docker / compose 设施与镜像层 nginx（少一跳转发、少一层缓存配置）。
2. **发布链路更轻**：发布包构建不依赖 docker daemon（任意 node 22 环境可出包），产物 tar.gz 自包含；服务器不维护历史版本目录，回滚由云效产物库重发承载。
3. **配置与证书路径统一**：`server.env` 与支付 PEM 证书（`/opt/apphub/pay-certs/`）两方案同路径，切换方案零配置变更。

## 后果

1. 上线批次（DEP-1~5）的服务器初始化按[发布包打包与部署指南 §5](../指南/发布包打包与部署指南.md) 执行（node 22 + rsync + systemd + nginx 站点），不再安装 docker。
2. 迁移执行点从「容器启动 entrypoint」变为「部署脚本 release.sh 显式执行」，两方案均为 ADR-005 语义（迁移是唯一建表通道）。
3. 全局 nginx 从「纯转发到容器 8080」（nginx-gateway）变为「静态托管 + API 反代」（nginx-site）；HTTPS 证书由该层统一终结。
