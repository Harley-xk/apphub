# 应用活跃度接入手册

> 面向桌面客户端（Electron / Tauri / 自研）开发者：把「有人在用」这件事实时、低打扰、可离线补报地上报给 apphub。
> 本册只约定**客户端上报协议**；统计口径、数据模型与服务端实现见 [应用活跃度统计设计](../应用管理平台/应用活跃度统计设计.md)。
> 签名算法与会员令牌不在本册重复定义：请求签名见 [会员认证接入手册](会员认证接入手册.md) §3，会员登录见同册 §5。

## 1. 先理解三个口径

| 概念 | 含义 | 客户端要做什么 |
| --- | --- | --- |
| 设备活跃 | 某自然日内该设备**窗口被激活过** | 上报 `activate` 事件（不是心跳） |
| 会员活跃 | 已登录会员在**登录之后**产生的活跃 | 上报时带 `Authorization: Bearer`；登录成功后立即补发一次 `activate` |
| 新增设备 | 该设备**第一次窗口激活**落在统计区间内 | 无需额外上报；首次 `activate` 自动建档 |

三条容易误解的规则：

1. **只有窗口激活才算活跃**。开机自启、托盘常驻、后台运行都不产生 `activate`，因此不会被算进日活（这正是我们要的效果）。
2. **匿名期不追溯**。会员在登录之前的匿名活跃永远不会计入会员口径；登录之后的活跃才归到会员。平台不做「设备当前绑定回溯」。
3. **一天多次使用只算 1 台设备 / 1 位会员**。同一天多次切窗、多次启动不会增加统计行，客户端可以放心合并上报。

> 会员口径的 UI 文案必须写清楚「会员 DAU = 登录态活跃，未登录使用不计入」。这是产品口径，不是数据缺失。

## 2. 接入准备

| 项 | 说明 |
| --- | --- |
| `appKey` | 应用标识，随客户端分发 |
| `appSecret` | 签名密钥。有服务端的应用由服务端代理签名；纯客户端形态须编入二进制（平台将此类应用标记为公开客户端并单独限流） |
| 服务基址 | 线上 `https://appcenter.witice.top`（不含 `/api`）；私有化 / 联调环境用平台方提供的基址 |
| 应用状态 | 只有 `enabled` 的应用可以上报；应用停用后验签直接 401 |
| 平台标识 | `windows` / `macos` / `linux` / `android` / `ios` / `web` |
| 架构标识 | 桌面端填 `x64` / `arm64` / `universal`；Web / 移动端可省略 |

### 2.1 请求头

| 请求头 | 必填 | 说明 |
| --- | --- | --- |
| `X-App-Key` | 是 | 应用标识 |
| `sign` / `timestamp` / `noncestr` | 是 | 应用级 HMAC 签名四件套（算法见[会员认证接入手册](会员认证接入手册.md) §3） |
| `Content-Type` | 是 | `application/json` |
| `X-Device-Id` | 建议 | 与请求体 `deviceId` **保持一致**。限流按 `AppKey + X-Device-Id` 计数；缺失时退化为全应用共享的 `unknown` 桶，容易被其他设备挤占 |
| `Authorization` | 否 | 已登录时带 `Bearer {accessToken}`。令牌无效 / 过期**不会导致上报失败**，服务端按匿名接收 |

> `X-Device-Id` 只参与限流，不参与签名；但请务必与 body 一致，否则限流桶与实际设备错位。

## 3. 上报接口

```text
POST /api/open/app/activity/report
```

### 3.1 请求体

```json
{
  "deviceId": "3f1c2a9e-8b7d-4c6a-9e2f-1a2b3c4d5e6f",
  "platform": "windows",
  "arch": "x64",
  "clientVersion": "1.4.2",
  "events": [
    { "type": "start", "occurredAt": "2026-11-13T09:12:03+08:00" },
    { "type": "activate", "occurredAt": "2026-11-13T09:12:05+08:00" },
    { "type": "activate", "occurredAt": "2026-11-13T10:30:41+08:00" },
    { "type": "stop", "occurredAt": "2026-11-13T18:02:11+08:00" }
  ]
}
```

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `deviceId` | 是 | 1~64 位，仅 `A-Z a-z 0-9 . _ -`；客户端首次启动生成 UUID v4 并持久化 |
| `platform` | 是 | 上述平台枚举之一 |
| `arch` | 否 | 桌面端必填；最长 16 位 |
| `clientVersion` | 是 | 合法 semver（如 `1.4.2`、`1.4.2-beta.1`），最长 32 位 |
| `events` | 是 | 1~50 条；超过 50 条返回 `700300002` |
| `events[].type` | 是 | `start` / `activate` / `stop` |
| `events[].occurredAt` | 是 | ISO 8601 且带时区（如 `+08:00` 或 `Z`） |
| `events[].eventId` | 否 | 客户端本地事件编号，仅排障透传，不落库、不参与幂等判定 |

### 3.2 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": { "accepted": 4, "ignored": 0, "memberResolved": true }
}
```

| 字段 | 含义 |
| --- | --- |
| `accepted` | 被接受并参与统计的事件数 |
| `ignored` | 因超窗 / 非法被静默丢弃的事件数 |
| `memberResolved` | 本次是否解析到有效会员态（`false` 表示按匿名入库） |

> `ignored > 0` 不是错误：单个事件时间超出 7 天回补窗口或超前服务器时间 5 分钟时会被丢弃，避免个别脏数据让客户端无限重试。

## 4. 事件语义与上报时机

| 事件 | 何时发 | 关键约定 |
| --- | --- | --- |
| `start` | 主窗口**首次对用户可见**时发一次 | 开机自启 / 托盘静默启动**不发**，直到窗口首次激活 |
| `activate` | 窗口获得焦点时发 | **1 小时内不重复发送**（本地节流）；冷启动首次可见时同时发 `start` + `activate` |
| `stop` | 正常退出时发 | 强杀 / 崩溃无法保证，不影响日活（当天已有激活即可） |
| 跨天补偿 | 窗口保持激活、本地日期翻篇时补发一条 `activate` | 每天最多一次，不受 1 小时节流限制；用于覆盖「通宵前台使用」 |

补充：

- **登录即活跃**：登录成功后立即补发一次 `activate`（绕过 1 小时节流），让会员口径及时生效。服务端不会反向从登录事件推导活跃。
- **离线队列**：本地最多缓存 200 条，恢复联网后按 ≤ 50 条/批补报；只保留 7 天内的事件，更早的直接丢弃。
- **本地合并（可选）**：发送前可把同一自然日、同一类型的事件合并为一条（保留最早 / 最晚时间即可）；服务端对合并与未合并两种形态都兼容，结果一致。
- **多设备 / 多安装**：`deviceId` 语义是「安装实例」，重装会生成新 ID，平台会将其视为新设备（已知偏差）。客户端 SDK 全局共用一个 ID，平台按 `(app_id, device_id)` 分别建档。

## 5. 客户端实现参考

以下 TypeScript 片段可跨 Node / Electron / Tauri WebView 使用；持久化层按平台替换（localStorage / 文件 / 系统偏好）。

### 5.1 签名与请求

```ts
const BASE = 'https://appcenter.witice.top'
const APP_KEY = '你的appKey'
const APP_SECRET = '你的appSecret'

function randomNonce(): string {
  return crypto.randomUUID().replaceAll('-', '')
}

async function hmacSha256Hex(text: string, secret: string): Promise<string> {
  const enc = new TextEncoder()
  const key = await crypto.subtle.importKey(
    'raw', enc.encode(secret), { name: 'HMAC', hash: 'SHA-256' }, false, ['sign'],
  )
  const sig = await crypto.subtle.sign('HMAC', key, enc.encode(text))
  return Array.from(new Uint8Array(sig)).map(b => b.toString(16).padStart(2, '0')).join('')
}

async function report(payload: unknown, accessToken?: string): Promise<ReportResult> {
  const path = '/api/open/app/activity/report'
  const body = JSON.stringify(payload) // 签的 = 发的：签名与发送复用同一字符串
  const timestamp = String(Date.now())
  const noncestr = randomNonce()
  const sign = await hmacSha256Hex(
    ['POST', path, body, timestamp, noncestr].join('\n'),
    APP_SECRET,
  )
  const headers: Record<string, string> = {
    'X-App-Key': APP_KEY,
    'X-Device-Id': (payload as { deviceId: string }).deviceId,
    'Content-Type': 'application/json',
    'sign': sign,
    'timestamp': timestamp,
    'noncestr': noncestr,
  }
  if (accessToken)
    headers.Authorization = `Bearer ${accessToken}`

  const res = await fetch(`${BASE}${path}`, { method: 'POST', headers, body })
  const json = await res.json()
  if (json.code !== 0)
    throw new ApiError(json.code, json.message, res.status)
  return json.data as ReportResult
}
```

### 5.2 节流、跨天补偿与离线队列（骨架）

```ts
interface QueuedEvent { type: 'start' | 'activate' | 'stop', occurredAt: string }

const ACTIVATE_THROTTLE_MS = 60 * 60 * 1000
const MAX_QUEUE = 200
const MAX_BATCH = 50
const KEEP_MS = 7 * 24 * 60 * 60 * 1000

class ActivityReporter {
  private queue: QueuedEvent[] = loadQueue()
  private lastActivateAt = 0
  private activeDay = ''

  /** 窗口首次可见 */
  onWindowShown(): void {
    this.enqueue('start')
    this.onWindowFocus(true)
  }

  /** 窗口获得焦点；force=true 用于冷启动 / 登录成功 / 跨天补偿 */
  onWindowFocus(force = false): void {
    const now = Date.now()
    if (!force && now - this.lastActivateAt < ACTIVATE_THROTTLE_MS)
      return
    this.lastActivateAt = now
    this.enqueue('activate')
  }

  /** 每分钟检查一次是否跨过本地自然日（窗口仍处于激活态时） */
  checkDayRollover(): void {
    const day = localDateKey(new Date())
    if (this.activeDay && day !== this.activeDay && document.hasFocus()) {
      this.activeDay = day
      this.onWindowFocus(true) // 跨天补偿：不受 1h 节流限制
    }
    else if (!this.activeDay) {
      this.activeDay = day
    }
  }

  /** 登录成功后调用：立即补发激活，让会员口径生效 */
  onLoggedIn(): void {
    this.onWindowFocus(true)
    void this.flush()
  }

  onExit(): void {
    this.enqueue('stop')
    void this.flush({ keepalive: true }) // 退出前尽量发出，失败留给下次启动补报
  }

  private enqueue(type: QueuedEvent['type']): void {
    this.queue.push({ type, occurredAt: new Date().toISOString() })
    const cutoff = Date.now() - KEEP_MS
    this.queue = this.queue.filter(e => Date.parse(e.occurredAt) >= cutoff).slice(-MAX_QUEUE)
    saveQueue(this.queue)
    if (this.queue.length >= 10)
      void this.flush()
  }

  async flush(options: { keepalive?: boolean } = {}): Promise<void> {
    while (this.queue.length > 0) {
      const batch = this.queue.slice(0, MAX_BATCH)
      try {
        await report({
          deviceId: getOrCreateDeviceId(),
          platform: detectPlatform(),
          arch: detectArch(),
          clientVersion: APP_VERSION,
          events: batch,
        }, getAccessToken())
        this.queue = this.queue.slice(batch.length)
        saveQueue(this.queue)
      }
      catch (error) {
        if (error instanceof ApiError && error.status === 429) {
          await sleep(30_000 + Math.random() * 30_000) // 429 退避，勿立即重发
          continue
        }
        if (error instanceof ApiError && error.status >= 400 && error.status < 500) {
          // 400 / 401 是确定性失败：丢弃该批，避免死循环（401 多为签名问题）
          this.queue = this.queue.slice(batch.length)
          saveQueue(this.queue)
          continue
        }
        return // 网络错误：保留队列，下次联网再补
      }
    }
  }
}
```

### 5.3 平台接入点速查

| 框架 | `start` / `activate` / `stop` 的挂载点 |
| --- | --- |
| Electron | `BrowserWindow` 的 `show` / `focus` / `close`；`app.on('before-quit')` 发 `stop`；`powerMonitor` 不做空闲过滤（本期不要求） |
| Tauri | `WindowEvent::Focused(true/false)`；`RunEvent::ExitRequested` 发 `stop` |
| 自研客户端 | 主窗口 `WM_ACTIVATE` / `NSApplicationDidBecomeActive` / X11 focus 事件；正常退出发 `stop` |

## 6. 错误码与重试

| code | HTTP | 含义 | 客户端处理 |
| --- | --- | --- | --- |
| `0` | 200 | 成功 | 正常出队 |
| `700300001` | 400 | 设备标识缺失或格式非法 | 检查 `deviceId` 与 `X-Device-Id`；丢弃该批（属实现错误） |
| `700300002` | 400 | 单次事件超过 50 条 | 按 50 条拆分后重发 |
| `700300003` | 400 | 上报应用不可用（停用 / 不存在） | 停止上报并提示「应用已停用」，不要循环重试 |
| `700300004` | 400 | 查询区间超过 180 天 | 仅管理端查询接口会出现，客户端不会遇到 |
| `700300005` | 403 | 无权查看该应用活跃度 | 仅管理端查询接口会出现 |
| `401` | 401 | 签名失败 / AppKey 无效 | 检查签名四件套与时钟；**不要**用无效凭据循环重试 |
| `429` | 429 | 超过设备限流阈值（120 次/分钟/设备） | 30~60 秒随机退避后重试；离线补报按批发送 |

> 事件时间超窗不会报错，只在响应 `ignored` 中计数。客户端无需为 `ignored` 重试。

## 7. 隐私与合规

- 平台只保存客户端**随机生成**的 `deviceId`、平台 / 架构 / 版本与三类业务事件时间。
- 不采集机器码、MAC、硬盘序列号、文件路径、窗口标题、应用使用内容，也不保存 IP（无事件明细表）。
- `deviceId` 不是机器指纹：清除应用数据或重装会重置，平台无法据此跨重装追踪同一台机器。

## 8. 验收清单

- [ ] 首次启动生成 `deviceId` 并持久化，重启后不变
- [ ] 冷启动可见时发出 `start` + `activate`；单纯托盘启动不发
- [ ] 1 小时内反复切窗只发一条 `activate`
- [ ] 窗口常开跨过 00:00 后补发一条 `activate`
- [ ] 登录成功后立即补发 `activate`，响应 `memberResolved = true`
- [ ] 断网期间事件进入本地队列，恢复后 ≤ 50 条/批补报成功
- [ ] 退出时发出 `stop`；强杀后下次启动仍能补报当天事件
- [ ] `X-Device-Id` 与 body `deviceId` 一致
- [ ] 收到 429 时退避重试，收到 400 / 401 不循环重试

## 9. 常见问题

**Q：为什么后台常驻一整天，日活还是没有？**
A：日活只看 `activate`。托盘常驻、开机自启不产生激活，属于设计内行为。如果用户确实长时间在前台使用，请确保实现了跨天补偿。

**Q：为什么会员 DAU 明显低于设备 DAU？**
A：会员口径只统计登录之后的活跃；匿名使用、未登录使用不会归到任何会员。这是严格时间切分的直接结果。

**Q：重装后新增设备数变多了？**
A：`deviceId` 语义是「安装实例」，重装会生成新 ID，属于已知偏差；平台不做机器指纹兜底。

**Q：可以只发 `start` / `stop` 吗？**
A：可以，但这类行不会计入 DAU / 区间活跃 / 新增设备。活跃判定以窗口激活为准。

**Q：需要心跳吗？**
A：不需要，也不要加。平台按「窗口激活」判定活跃；无条件心跳既增加请求量，也会污染前台挂机场景（本期不做系统空闲检测）。
